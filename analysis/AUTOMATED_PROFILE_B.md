# Profile B local release candidate / Candidate locale de diffusion du profil B

## English

`prepare-automated-profile-b` prepares `dwr-automated/2.0.0` locally from the existing native source-admission chain. This major version implements profile B: it removes **every daily family/role margin** while retaining monthly resource/actor detail, monthly family totals, daily site/role counts, minimal coverage and constant U0. G06 remains a monthly family figure. It does not acquire data, publish, register a public edition, change `latest`, move the historical cursor or activate a schedule.

Use a new private workspace outside Git, separate from the v1 candidate, with byte-identical accepted acquisition, import receipts, pinned source evidence and normalized/qualified inputs. Preserve the old candidate and its receipt. The only new command is:

```powershell
python -I -B scripts/dwr.py prepare-automated-profile-b --private-root $privateRoot
```

The window comes from the existing source contract; `--edition` is refused. No clock, publication, diagnostic substitution or synthetic override is exposed. The command reconstructs the native sources even when normalized/qualified inputs are already present. It installs under `automated-profile-b/candidates/<window-r1>/` with a separate `automated-profile-b/status.json`. A common root reservation is acquired before either version creates its namespace; a second separation check under that reservation rejects a stale losing command without poisoning the winning candidate. The existing namespace lock and staged installation still prevent partial candidates. Changed inputs or outputs require inspection and a distinct revision; an unchanged replay can only restore this separate status file.

The versioned canonical document, closed schema, catalog, figure registry, manifests, CSV, JSON, SVG and FR/EN reports are generated together. The document has `availability_status=local_release_candidate` and `public_output_approved=false`. This describes an unreleased artifact; neither preparation nor structural verification authorizes an external action. There are 56 projection files, including seven tables. The entire candidate remains private: source diagnostics and the preparation receipt are outside the projection allowlist. Never copy the entire private workspace into a public repository.

The monthly tables retain site, resource path/family and software actor family/name/role at window granularity. No resource/actor days, first/last timestamps or epoch partitions are added. The daily table contains the complete site/role calendar; unavailable days stay null, not zero. The family-daily table is absent from projection JSON, schema, CSV, catalog, report links and manifests. Unexpected fields, directories or files are rejected, as are inconsistent marginals and noncanonical regenerated bytes.

`diagnostics/profile-b-inference.private.json` reports exact cell bounds in the reduced numeric model. Within each site/role, a complete nonnegative integer transportation table connects monthly resource/actor totals `c` to daily totals `d`, with common total `T`. Each cell ranges from `max(0,c+d-T)` to `min(c,d)`. The calculation reads only canonical B margins, not the original day/resource assignments. It checks all observed days and positive monthly columns, including forced zeros. Its proof scope excludes auxiliary knowledge and semantic support restrictions. Small or concentrated datasets can still fix positive cells; the implementation never equates this profile with anonymity or a universal non-reconstruction guarantee. The private diagnosis is not an additional release surface.

The on-demand block remains U0, `withheld_not_zero`, count null and initiation unknown. Classifier and measurement-epoch limitations remain categorical. Unqualified comparison stays null; documentary graphs remain unavailable. A recorded role does not establish actual training, citations, discovery, causal effects or a person’s activity.

The v1 entry point and generated schema remain available. Its canonical JSON still regenerates the original 57 output bytes under `dwr-automated/1.0.0`; this does not convert v1 into profile B. Preparation receipts bind raw code/input bytes, including line endings. Replay a sealed candidate from its exact archived code export; a CRLF working copy is not a byte-equivalent replacement for an LF export. Preparation receipts bind their full code/input manifest, so an old sealed preparation is replayed using its archived code, not silently repinned to newer source. The M1 renderer, public registry and historical policies remain unchanged. The historical publication gate does not acquire new M2 authority from this local candidate.

Validation commands:

```powershell
python -I -B -m unittest discover -s tests -t . -p test_automated_profile_b.py -v
python -I -B -m unittest discover -s tests -t . -p test_automated_contract.py -v
```

Tests distinguish a changed daily family allocation from unchanged allowed margins, validate all output bytes, compare bounds with an exhaustive small-table oracle, reject corruptions and exercise native source admission through the real CLI dispatcher with a fixed test clock. Real-data qualification, FR/EN mobile/desktop screenshots and a consolidated independent review remain separate evidence tied to the exact final candidate. Any later publication requires its own named external authorization and a current combined-history review; no public availability or scientific approval is inferred from a local GO.

## Français

`prepare-automated-profile-b` prépare localement le contrat distinct `dwr-automated/2.0.0`. Le profil B retire toutes les marges « jour × famille × rôle » et leurs dérivés, tout en conservant les détails mensuels de ressources et d’acteurs, les synthèses mensuelles par famille, les comptes « jour × site × rôle », la couverture minimale et U0. G06 reste mensuel. Aucune acquisition, publication, inscription publique d’édition, modification de `latest`, déplacement du curseur historique ou activation de calendrier n’a lieu.

Utiliser un nouvel espace privé extérieur aux dépôts Git, distinct de la candidate v1. Copier à l’identique l’acquisition admise, les reçus d’import, les sources épinglées et les intrants normalisés/qualifiés. La commande PowerShell ci-dessus reconstruit l’admission native avant d’installer la candidate dans `automated-profile-b/candidates/<fenêtre-r1>/`. Son état reste séparé. Les deux commandes réservent la même racine avant de créer leur dossier de version, puis revérifient la séparation sous cette réservation. Une commande perdante ne laisse donc aucun dossier qui bloquerait le rejeu de la candidate gagnante ; le verrou de version existant est conservé. L’option `--edition` est refusée ; aucun remplacement par un diagnostic ou une simulation n’est offert. Les candidates existantes ne sont pas réécrites ; seul l’état séparé peut être rétabli lors d’un rejeu identique.

Les 56 fichiers de projection sont générés ensemble : document canonique, schéma fermé, catalogue, registre des figures, manifeste, sept tables, métriques, figures et rapports FR/EN. Le statut `local_release_candidate` et `public_output_approved=false` désigne un artefact non diffusé. Les diagnostics et le reçu de préparation demeurent privés, en dehors de cette liste fermée. Ne jamais copier la candidate complète ou son espace privé dans une diffusion.

La table quotidienne par famille est absente du JSON canonique, du schéma, du CSV, du catalogue, des liens et des manifestes. Les comptes par site/rôle restent quotidiens ; les détails de ressources, d’acteurs et de familles restent mensuels. Aucun compte de jours actifs, premier/dernier accès ou partition d’époque n’est ajouté. Une date indisponible reste null et un zéro sous couverture partielle signifie seulement qu’aucune ligne sélectionnée n’a été enregistrée.

Le diagnostic privé calcule les bornes exactes du modèle réduit de tables de transport, par site/rôle : `max(0,c+d-T)` à `min(c,d)`. Il utilise uniquement les marges canoniques B. Les informations auxiliaires et contraintes sémantiques restent hors modèle. Des groupes petits ou concentrés peuvent encore fixer des cellules positives ; aucun anonymat ni absence universelle de reconstruction n’est affirmé. Ce diagnostic ne devient pas une surface de diffusion.

U0 demeure constant, avec compte null et initiation inconnue. Les limites du classificateur et des époques, la croissance null et les graphes indisponibles sont conservés. Les rôles enregistrés ne prouvent ni entraînement effectif, ni citation, ni découverte, ni causalité ou activité d’une personne.

Le lecteur v1 et ses 57 sorties demeurent distincts et reproductibles. Les reçus épinglent les octets du code, fins de ligne comprises : utiliser l’export archivé exact pour le rejeu, sans substituer une copie CRLF à un export LF. Les reçus v1 épinglent le code original : le rejeu d’une préparation historique utilise l’export archivé, sans remplacer les empreintes par celles du nouveau code. Les éditions M1, leurs politiques, leur registre public et leur contrôle de diffusion restent inchangés.

Les tests ci-dessus vérifient la non-divulgation de la marge retirée, les octets déterministes, les bornes contre une énumération exhaustive, les refus d’altération et l’admission native par le véritable répartiteur CLI avec une horloge de test fixe. Les preuves sur les données réelles, les captures FR/EN mobiles et bureau et l’audit indépendant doivent être liées au candidat final exact. Une diffusion ultérieure exige l’autorisation externe nommée et une revue de l’historique à jour ; un GO local ne certifie ni disponibilité publique ni validité scientifique.
